# UIManager

Короткая памятка для AI-агентов перед правками `Assets/Scripts/UI/General/UIManager.cs` и связанных окон.

`UIManager` - координатор UI сцены. Он не создаёт окна: все окна уже должны лежать дочерними объектами в UI-префабе/сцене и реализовывать `IWindow`.

Главная модель простая:

- `ShowWindow<T>(args)` находит дочернее окно, кладёт его в стек, вызывает `SetArgs(args)`, затем `Show()`.
- `HideWindow<T>()` или `HideWindow(IWindow)` удаляет окно из стека, вызывает `Hide()`.
- После каждого открытия/закрытия вызывается `Inputs.UpdateActionMaps(this)`.

Поэтому не открывай и не закрывай окна напрямую через `window.Show()`, `window.Hide()` или `gameObject.SetActive()`, если это влияет на игровой UI. Иначе стек окон и input maps разъедутся.

`VisibleWindowCount`, `HasModal()` и верхнее окно стека используются `Inputs` для выбора action maps: игровое управление, UI, глобальные хоткеи, window-specific maps. Если добавляешь новое окно, проверь его `IsVisible`, `IsModal`, `ActionMap` и `SetArgs`.

`args` в `ShowWindow<T>(args)` намеренно нетипизированный. Его смысл задаёт конкретное окно. Перед изменением вызова проверь `SetArgs` нужного окна.

В `Init` сервис прогревает дочерние окна: временно активирует найденные `IWindow`, затем снова скрывает их. Не удаляй это без проверки lifecycle UI-компонентов.

Для контейнеров, крафта, карты и диалогов сначала смотри связанное окно и событие, а уже потом меняй `UIManager`.
